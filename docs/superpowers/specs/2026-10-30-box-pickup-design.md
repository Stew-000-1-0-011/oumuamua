# field.yaml の初期座標による箱回収

## 目的・選択済みの方法

箱回収を再実装し、既存 `field.yaml` の `field.notes_x` に5個の箱中心x座標 [m] を並べて使う。
2026-10-30、ユーザーは既存YAMLによる設定を選択した。配列順を箱番号0〜4とし、内部でソートしない。
`field.notes_y` と `field.note_size` は共通値として引き続き読む。コントローラは箱番号と左右把持機構を選ぶ現状の操作を保つ。

検討した代替はコントローラへの5座標入力欄・通信・設定サービスの追加。今回は不要と判断された。
コントローラは同じfieldファイルから個数を読み、既に可変個数の回収ボタンと回収状態表示に対応しているため、原則変更しない。

## 現状の問題

- 回収姿勢は吸着面の仮オフセット `[0.45, ±0.12]` と固定yawで決め、機体は半径0.32 mの円として検査している。端の箱に対して到達できない組合せがある。
- 接近前に選択側の昇降を下げるため、長い移動と最終接近の形状を分けていない。
- 吸着開始後の失敗・取消について、箱が回収可能か、把持機構が空いているかを保守的かつ一貫して扱う必要がある。
- controllerは状態をtask_commanderから受け取っており、成功通知だけを根拠に回収済みにする仕組みではない。

## 回収動作

1. 番号・保持状態・初期配置・自己位置と設定値を検査する。既に保持中の把持機構、回収済み/状態不明の箱は拒否する。
2. 現在位置から回収前位置までの移動、最終接近、持ち上げ後の退避を事前に計画・検証する。安全な候補がなければ、機構や吸引を動かす前に理由を返す。
3. 全昇降をcarryへ上げ、到達を待ってから回収前位置へ移動する。
4. 選択側だけclearへ下げる。回収前位置から対象箱の真上へ低速で接近する。
5. 選択側をpickへ下げ、吸引をオンにし、設定した把持待ち時間後にcarryへ上げる。
6. carry到達を確認し、箱と把持機構の保持状態を確定して低速で退避する。退避のみの失敗では保持記録を消さない。

吸着を物理的に検出するセンサーは既存インターフェースにない。したがって「保持」は吸引指令と昇降到達に基づく制御上の記録であり、吸着の実測保証とはしない。
吸引要求を送った後に応答が不明・取消・昇降失敗となった場合は、箱/把持機構を状態不明として再利用を禁止する。
既存controller用のholding/picked表示では、この状態も使用不可として伝え、失敗理由に復旧確認が必要であることを表示する。
吸引前の失敗では未回収のままにする。resetは従来同様、作業停止中に実物と記録を合わせるための明示操作とする。

## 経路と形状

- 吸着面オフセットは `grippers.offsets` を使い、CADの外形から吸着面の位置を推測しない。実測校正用の設定として残す。
- 既存 `pick.yaw` を優先し、その前後の候補角でも到達姿勢を計算する。候補角は設定可能とし、通過可能な候補を選ぶ。
- 直接の移動、または箱列より外側の共通通路 `pick.transit_y` を経由する移動を検査する。スラロームを横断して箱へ向かう自動計画は今回の対象外。
- 最終接近と退避は箱列から離れる +y 方向の回収前位置と対象姿勢を結ぶ。長い移動は全昇降上で行う。
- 添付の上/下フットプリントと確認済みの変換 `(x_base,y_base)=(-y_attachment,x_attachment)` を利用する。上形状は移動、下形状はclear/pick姿勢と最終接近の保守的な外形として使う。
- 形状が壁・棚・外周・未回収の他の箱に触れないことを、位置/yaw補間を含めて検証する。最終接近で対象箱と重なる吸着部は意図した接触として扱い、足回りの上形状は対象箱に対しても検査する。
- 接触除外は選択側の領域だけを明示する。添付の約150 mm角の前方パッドに対応するbase_link上の矩形を設定し、下形状全体を対象箱の検査から外さない。領域の対応と吸着中心オフセットは別物として記録し、校正可能にする。
- 33 mmの共有フィールドを変更せず、スラロームと同じ内壁片側2.5 mm・外周内面5 mmの余裕を適用する。回収時の非接触間隔は既存の20 mmを起点とする。
- 他の移動/配置タスクのアルゴリズムや速度上限は変更しない。

## 入力・設定

初期設定は既存配列の先頭5値 `[-2.699, -2.499, -2.299, -2.099, -1.899]` を暫定値として残し、現場の5実測値に置換できるようコメントと例を書く。
5個という運用は設定で表し、コード内へ箱座標や個数を固定しない。配列空・非有限値・箱同士の重なり・フィールド外の配置は起動時に拒否する。
controller bridge、位置推定、シミュレータ、task_commanderは同じfieldファイルを読み、変更後は関連ノードを再起動する。

## 実装と確認

ROS非依存のC++計画・形状検証と回収状態遷移をテスト可能に分け、既存task_commanderが計画の各段階を実行する。
形状ファイルは既存の原本を共有し、起動時にbase_linkへ変換した点列を渡す。吸着面オフセット・昇降番号・高さは実機校正値を設定で指定する。
テストは5座標の番号保存、不正配置、端の箱、左右の違い、他の箱/壁との衝突、移動中の回転、保持中の拒否、吸引前/後の失敗・取消、退避失敗、再試行を含める。
既存スラロームの16件とC++軌道テストも再実行し、別エージェントが最終差分をレビューする。

今回の成果は回収処理・設定・テストと検証用の経路図。実機の吸着成立、寸法校正、全ROS実行を未実施の場合に成功済みとは報告しない。
